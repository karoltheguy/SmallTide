## Verified correct (matches the reference)
- Loop structure: prelude 0-5, core 6-17 x3, coda 18-23; pass>0 restarts from prelude state; messages from
  `blocks[num_pre+1:]` + previous pass hidden; message gate `(1-tanh(forget))*h + tanh(gain)*msg` on
  `[unit_rms(h), unit_rms(msg)]`; sliding loop layers gate before `input_layernorm`, full loop layers gate the
  3 mixes then q/k/v norms; MLP gate after `mlp_input` mix.
- Message query merge `[q[2i], kv[2i], kv[2i+1], q[2i+1]]`; `attn_queries.{i}` -> layer i+1.
- Full layers = 5, 11, 17, 23 (attn_queries 4/10/16/22 are [3,2304]).
- w13 interleave (row 2r gate, 2r+1 up); NVFP4 low nibble first, x block fp8 scale x amax/denom;
  MXFP8 scales are [N, K/32] UE8M0 (1-D, not 32x32 as PLAN.md says); .stide size matches exactly.
- static_w tap index = lag (flip in dense_loader is right); conv1d weights in conv order; /sqrt(5) static,
  /3 dynamic; k clip after sconv; v unit-RMS; q/r scaled clip; tau after clip on full layers; sink logit
  with zero value; rel bias zero beyond extent; router sigmoid + bias for selection, weights without bias,
  normalized x 8; SiTU activation; final mix -> norm -> unembed -> softcap 30.
- All kernels compile for gfx1201 with clang-19 (no spills).

## Bugs found (Tide runtime) — not yet fixed in the repo
1. Async promotion race (`TideExecutor::execute_transfers`, `post_decode_tide_step`): copy stream overwrites
   an evicted expert's VRAM slot without waiting for compute that may still read it, and the whole GPU slot
   table is re-uploaded on the copy stream while compute kernels read it (stale mapping -> reads a slot that
   is being rewritten). Fix: record an event on compute, copy stream waits it before overwriting; upload
   unmaps on the compute stream immediately; map new experts only after their DMA event (next token),
   i.e. add a `vram_pending` state so CPU never counts an in-flight expert as a hit.
2. Sync rescue in `plan_layer_dispatch` -> `promote_to_vram` can evict another expert of the SAME layer's
   current top-8 (kernel then silently skips it). Pass the current top-k as protected from eviction.
3. `promote_to_vram` falls back to `DiskToVramDirect` (blocking NVMe read) when RAM isn't ready; this is hit
   from periodic rebalance / boundary rebalance inside decode. For async paths queue Disk->RAM instead.
4. `RamToVram` silently DMAs stale staging bytes if `ram_slabs` lacks the slab — should be an error/fallback.
5. Fully-resident layers never call `touch_expert`, so heat (eviction policy, priors) only sees partial layers.
   Fix: router writes ids/weights into a per-logical-layer log buffer, one async D2H per token.
6. `memcpy_d2h_sync` uses blocking `hipMemcpy` per call (2 per partial layer + 2 for argmax): combine.

## Performance notes
- Prefill is token-at-a-time through the decode path (~20 tok/s). Needs a rows-batched forward:
  batched FP8 GEMM (exists, BM=8; later WMMA fp8), rows variants of mix/sconv/clip/kv-store/attention/router,
  expert-major grouped MoE for prefill (host-planned pair lists, missing experts staged through scratch).
  Local KV ring must grow to window + chunk (e.g. 2048) for chunked prefill.
- Decode bytes/token ~3.6 GB (dense FP8 ~1.3 GB over 48 logical layers, experts ~1.84 GB, lm_head 0.46 GB):
  ~8 ms at 450 GB/s -> ~100 tok/s is the ceiling, needs ~70% BW + hipGraph (launches ~1100/token).
  For graphs: read `pos` from a device u32 in kv-store/attention/tau kernels; fixed split count with early exit.
  Fuse rel_table into attention (16 MACs/score) to drop a launch per layer.
- Controllers are FP32 in the reference (BF16 in the checkpoint): keep them BF16 rather than FP8 (~57 MB).
